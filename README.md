# dsh-oauth-adapter

English | [中文](README.zh.md)

OAuth sign-in and account model management for the DSH Web profile. The validation baseline is DSH `0.1.2-rc.1`, with an exact plugin dependency on pi-ai `0.84.4`. Synchronizing models never installs or upgrades packages.

## Install

```sh
dsh plugin --profile web add @edge-sky/dsh-oauth-adapter
dsh web
```

Use **Settings → OAuth Accounts** to connect or reconnect an account. Successful authorization automatically synchronizes its models. Authorization and synchronization have separate results: a discovery failure does not undo successful sign-in.

Use the **OAuth models** area of **Settings → Models** to synchronize an existing connection, configure unmatched models, and add, edit or delete manual entries. This area occupies the public `settings.models.footer` slot. No additional model settings page is installed.

| Provider | Model protocol |
| --- | --- |
| GitHub Copilot | Select Chat Completions, Responses or Anthropic Messages per model |
| OpenRouter | Select Chat Completions or Anthropic Messages per model |
| OpenAI Codex | Codex Responses |
| xAI | OpenAI Responses |
| Anthropic, Kimi Coding | Anthropic Messages |

Model ID is required; a blank display name uses the ID. Fixed-protocol providers have no protocol selector and reject protocol overrides on the server. An unknown model receives the provider's configured default capacities, text input and no inferred reasoning capability. Saving permits an attempted request; it does not prove the model exists, that the account can call it, or that all capabilities are known.

## Synchronization

Discovery uses each provider's authenticated endpoint, including Copilot's OAuth-resolved API host, Codex's account header, Anthropic cursor pagination and OpenRouter's account-filtered offset pagination. OpenRouter's public catalog is not used as a substitute. An unsupported endpoint or insufficient OAuth scope is reported and manual configuration remains available. Endpoint details and references are in [migration and operation](docs/oauth-models.md).

Only exact IDs within the same provider inherit pi-ai's full model metadata. No display-name matching or undocumented alias inference selects a protocol. Unknown IDs remain **Needs configuration**. Successful synchronization replaces automatic entries with the complete remote result, including a genuinely empty result. Manual entries survive and merge by ID with explicit user fields winning. Errors retain the last successful result. Before any successful discovery, the previous configured or built-in list remains available and is labeled unverified. Reconnection to a different or unidentifiable account clears the old account's automatic results before discovery.

The plugin stores model settings in `oauth-models`, including a version, migration backup, cached remote IDs and manual entries. Credentials remain exclusively at `llm-pi-ai/<provider>` through DSH's credentials service. Public pi-ai authentication handles token refresh; tokens never enter model settings or browser messages. A future plugin dependency upgrade rematches cached IDs against the newly loaded catalog.

Existing provider IDs and session references remain unchanged. Simple profiles generated by earlier plugin versions migrate automatically; custom profiles require a preview in Models. API-key references, composition-owned profiles and competing adapters are not overwritten. See [migration and recovery](docs/oauth-models.md#migration-and-recovery) before upgrading a customized installation.

## Configuration

The optional Host plugin configuration accepts:

| Field | Default | Meaning |
| --- | --- | --- |
| `debug` | `false` | Transport lifecycle diagnostics |
| `modelSyncTimeoutMs` | `30000` | Discovery and route-release timeout |
| `modelSyncMaxResponseBytes` | `4194304` | Maximum bytes per remote page |
| `modelSyncMaxPages` | `100` | Maximum pages per synchronization |
| `codexClientVersion` | `0.149.0` | Version sent to the Codex discovery endpoint |

## Development and verification

```sh
pnpm install
pnpm run typecheck
pnpm test
```

Tests cover provider responses, matching, retained results, revisions, migration recovery, cancellation, actual rc adapter requests with network interception, and published rc model-page bundles in a DOM environment with replayable snapshots. WebSocket tests bind a loopback port. All test credentials are synthetic; these checks do not establish live-account discovery or inference success for any provider. DSH source changes are not required.

## Local package and installation verification

`npm pack` and `npm publish` from the package directory run type checking, a fresh build, and tests through `prepack`; a failure stops packaging. Do not bypass this check with `--ignore-scripts`. Published versions cannot be overwritten, so a fixed release needs a new version number.

A temporary `DSH_HOME` lets you test a local tarball without affecting existing accounts or profiles or changing DSH code:

```sh
pnpm install --frozen-lockfile
artifact_dir=$(mktemp -d)
npm pack --pack-destination "$artifact_dir"
export DSH_HOME=$(mktemp -d)
mkdir -p "$DSH_HOME/profiles/web"
cat > "$DSH_HOME/profiles/web/pnpm-workspace.yaml" <<'YAML'
packages:
  - .
nodeLinker: hoisted
autoInstallPeers: false
allowBuilds:
  '@google/genai': false
  protobufjs: false
YAML
npx @deepseek-ai/dsh@0.1.2-rc.1 plugin --profile web add "$artifact_dir"/*.tgz
npx @deepseek-ai/dsh@0.1.2-rc.1 web --no-open
```

After stopping the server, run `unset DSH_HOME` to restore the default directory. The test profile explicitly skips installation scripts for these two dependencies; the plugin repository's policy does not propagate to consumers. New users still need to configure this policy in their own profiles. Successful startup verifies plugin loading; real-account login, model discovery, and inference need separate verification.
